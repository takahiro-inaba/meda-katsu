## ループ #1 — 台帳とグラフの土台

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 一番解決したいことは | 生き物の台帳管理 と 水質の推移を見ること（2つ） |
| どんな環境で使うか | PC の Web アプリ |
| データはどこに保存するか | ブラウザ内 |
| 最初に扱う管理対象は | 生き物 / 水質・水温 / 作業ログ |

### 決めたこと

- **サーバなし。** `localStorage` に JSON をまるごと保存する。バックアップは JSON のコピー &
  貼り付けで行う（ファイルのダウンロードは環境によって塞がれるため使わない）。
- **依存ライブラリなし。** グラフも SVG を直接組み立てる。`index.html` を開けば動く状態を保つ。
- **水温と pH は別グラフ。** ひとつの縦軸に 2 つの尺度を載せると値を読み違えるため。
- **削除は確認ダイアログではなく取り消し。** `confirm()` は環境によって出せないことがあり、
  やり直せる方が速い。
- **ビオトープは複数持てる形にした。** 要求としては聞いていないが、後から複数化すると
  既存データの作り直しが必要になるため、最初から `biotopeId` を持たせた（→ 要確認）。

### 積み残し（次のループの候補）

- 生き物の**増減の履歴**がない。いまは「今の数」だけを持ち、増えた / 減った経緯は残らない。
  繁殖や死亡を追いたいなら出来事として記録する形が要る。
- **水草・底床・機材**は未着手。最初の要求で外した分。
- 水質は**水温と pH のみ**。亜硝酸・硝酸塩・KH などは項目として持っていない。
- **リマインド**がない。「最後の水換えから何日」は出すが、通知や予定はない。
- **写真**が付けられない。`localStorage` の容量（数 MB）に収まらないため設計が要る。
- 期間の絞り込みは 30 / 90 / 全期間の固定。任意の期間指定はできない。

## ループ #2 — 生き物の増減の履歴

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | 生き物の増減の履歴 |
| ビオトープの複数対応は要るか | 複数あるので残す |

### 決めたこと

- **数を持たない。** `creature.count` を捨て、出来事（導入 / 繁殖 / 死亡 / 譲渡 / 数え直し）だけを
  保存する。いまの数は出来事を古い順に積み上げて計算する。
  数を直接書き換える作りだと「12匹が8匹になった」しか残らず、原因が消えるため。
- **「数え直し」を絶対値の置き換えにした。** ミナミヌマエビやタニシは正確に数えられない。
  ＋−では表せない「数えたら34匹だった」を扱えないと、記録が現実と合わなくなる。
- **合計匹数のグラフは階段状にした。** 数は出来事があった日にだけ変わり、その間は一定なので、
  点を斜めに結ぶと「毎日少しずつ増えた」という嘘になる。
- **旧データは自動で移行する。** v1 の `count` を導入日の「導入」1件に読み替える（`migrate()`）。
  保存キーは変えていないので、前のバージョンで記録していても開くだけで移る。
- **削除は生き物と履歴をまとめて消す。** 履歴だけ残っても参照先がない。取り消しは可能。

### 積み残し（更新）

- **水草・底床・機材**は未着手。
- 水質は**水温と pH のみ**。亜硝酸・硝酸塩・KH などは持っていない。
- **リマインド**がない。「最後の水換えから何日」は出すが、予定や通知はない。
- **写真**が付けられない。`localStorage` の容量に収まらないため設計が要る。
- 匹数のグラフは**合計のみ**。種類ごとの内訳は出せない。
- 期間の絞り込みは 30 / 90 / 全期間の固定。

## ループ #3 — 写真

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | 写真を残す |

### 先に確かめたこと

`file://` で開いたときに `IndexedDB` が使えるか。ここが駄目なら設計が変わるため、
コードを書く前に実機（Chromium）で確認した → **使える。割り当ては約 965MB**。

### 決めたこと

- **保存先を分けた。** 記録の JSON は `localStorage`、画像そのものは `IndexedDB`。
  `localStorage` は全体で 5MB 程度しかなく、写真 1 枚で使い切るため。
- **取り込み時に長辺 1600px の JPEG へ縮める。** 端末の写真は数MBあり、そのまま貯めると
  すぐ容量に当たる。4000×3000 の画像が 30KB になることを確認した。
- **バックアップ JSON に写真は含めない。** 貼り付けで運べる大きさを超えるため。
  ダイアログにその旨を明記した。写真を別端末へ移す手段は未提供（積み残し）。
- **写真の削除だけは取り消せない。** 画像は復元できないので、記録だけ戻しても壊れた参照が残る。
  逆に作業ログを削除したときは写真を消さず、「写真」画面に残す。
- **画像の表示は後から差し込む。** `IndexedDB` は非同期なので、描画は `img[data-photo]` の
  ままにしておき、読めた順に `src` を入れる。`objectURL` は使い回してちらつきを防ぐ。

### ついでに直したこと

種別チップ（作業ログ・増減）を押すと画面全体を描き直していたため、**入力途中のメモや
選択したファイルが消えていた**。ループ#1 から埋まっていたが、写真の添付を足したことで
表面化した。チップの選択状態だけを更新するようにした。

### 積み残し（更新）

- **写真を別端末へ移せない。** バックアップは記録のみ。
- **水草・底床・機材**は未着手。
- 水質は**水温と pH のみ**。
- **リマインド**がない。
- 匹数のグラフは**合計のみ**。種類ごとの内訳は出せない。
- 期間の絞り込みは 30 / 90 / 全期間の固定。
- 写真の並べ替え・絞り込みがない（新しい順のみ）。

## ループ #4 — 水草・底床・機材

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | 水草・底床・機材 |

最初の要求で外した最後の管理対象。これで当初の「ビオトープ全体」が一通り揃った。

### 決めたこと

- **3 つを別々の表にしなかった。** 水草・底床・機材は性質が違うが、「入れた → 使っている →
  撤去した」という一生は同じ。種別を持つ一つの表にして、画面上で 3 つに分けて見せる。

  使っていたかは、うまくいかなくなったときに効いてくる記録なので消さない。
- ダッシュボードの「記録の数」タイルを「水草・設備」に差し替えた。件数は眺めても
  行動が変わらないが、設備の点数と内訳は変わる。

## ループ #5 — スマホ対応

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | スマホ対応 |

ループ#1 で「PC の Web アプリ」と決めた前提が変わった。記録するのはビオトープの前
＝スマホ、というのは実際に触ってみて出てきた要求。**先に仕様を固めていたら拾えなかった。**

### 決めたこと

- **下部タブバーにしなかった。** 項目が 6 つあり、狭い画面に文字を並べると読めない。
  アイコンを新たに 6 つ作るより、上部固定の横スクロールするタブの方が正確で軽い。
  選んだタブは `scrollIntoView` で見える位置に寄せる。
- **表は 1 行 1 カードに組み替えた。** 横スクロールする表では右端の操作列に指が届かない。
  各セルに `data-label` を持たせ、CSS の `::before` で見出しを出す。
- **グラフは座標系そのものを狭くした。** SVG は横幅いっぱいに拡大縮小されるので、
  座標系と表示幅が離れるほど目盛りの文字だけが小さくなる。スマホでは 760 → 340 にして
  拡大率を 1 に近づけた（実測 0.98、目盛り 10.7px）。
- **入力欄の文字は 16px。** これ未満だと iOS が勝手に画面を拡大する。
- **固定ヘッダーは 2 段まで。** ブランド名とバックアップボタンを外し、
  バックアップはダッシュボードの末尾に移した。

### 詰まったところ

画面が横にはみ出す（586px > 390px）。原因は `.app` のグリッド指定 `1fr`。
これは `minmax(auto, 1fr)` の略で、中身の最小幅より縮まない。`minmax(0, 1fr)` に直した。
最初はタブ帯の負マージンを疑って直したが、それは症状の一部でしかなかった。

### 積み残し（更新）

- **写真を別端末へ移せない。** バックアップは記録のみ。
- 水質は**水温と pH のみ**。
- **リマインド**がない。
- 匹数のグラフは**合計のみ**。
- 期間の絞り込みは 30 / 90 / 全期間の固定。
- 写真の並べ替え・絞り込みがない。
- 水草の**トリミングや植え替え**は作業ログの「その他」に書くしかない。
- **オフラインで開けない。** Service Worker がないので、スマホのブラウザで
  ページ自体を読み込めない状況では使えない。

## ループ #6 — 記録からの気づき

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | AI サジェスト機能。日々の記録から AI がアドバイス |

### 先に確かめたこと

公開ページ（Artifact）から Claude API を呼べるか → **呼べない。**
ページに与えられる実行時の能力は `downloads` と `mcp`（claude.ai のコネクタ）だけで、
LLM を直接叩く口はない。CSP が外部ホストへの通信そのものを遮断する。
そもそもこのアプリはサーバも API キーも持っていない。

### 決めたこと

- **まず、外部に依存しない部分を先に作った。** 記録から機械的に導ける指摘を出す。
  キー不要・オフラインで動く・データが外に出ない。ここは要求の答えがどうであれ必要になる。
- **「AI が言っている」という見せかたをしない。** 中身は決定的な規則なので、
  名前は「気づき」にした。LLM を使っていないものを AI と呼ぶと、
  当たっているかの判断基準を読み手から奪う。
- **どの指摘にも根拠の数字を添える。** 「水換えから間があいています」だけでは動けない。
  「45日前。普段はおよそ12日おき」まで出して初めて判断できる。
- **段階は 4 つ**（気になる / 注意 / 参考 / 順調）。色だけに頼らず、記号と言葉も付けた。

見ているもの: 水温の高さと急変、pH の範囲と振れ幅、水換えの間隔（過去の中央値との比較）、
死亡と繁殖、数が長く動いていない生き物、底床の使用年数、記録と写真の途切れ。

### 未決

LLM に投げる版をどうするか。API キーをユーザー自身に入れてもらう形なら
1ファイル版では動くが、公開ページでは動かない。次のループで決める。

### 積み残し（更新）

- **写真を別端末へ移せない。**
- 水質は**水温と pH のみ**。
- **リマインド**がない（気づきは出るが、予定や通知はない）。
- 匹数のグラフは**合計のみ**。
- 期間の絞り込みは 30 / 90 / 全期間の固定。
- 写真の並べ替え・絞り込みがない。
- **オフラインで開けない。** Service Worker がない。

## ループ #8 — 測定時刻

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| （指摘） | 水質の変化は測定時刻も重要。朝なのか昼なのかでも水温は変わる |

**モデルの欠陥の指摘だった。** 測定が `date` しか持っていなかったため、朝6時の22℃と
昼2時の29℃が同じ折れ線に並び、「気づき」でも急変として誤検出していた。
それは水温の変化ではなく測定時刻の差でしかない。

### 決めたこと

- **測定に `time` を足した（v5）。** 時間帯は 朝(4〜10) / 昼(10〜16) / 夕夜(16〜4)。
- **古い記録の時刻は作らない。** `null` のまま「時刻不明」として扱う。
  もっともらしい時刻を埋めると、記録が事実でなくなる。
- **急変の判定を同じ時間帯どうしに変えた。** 直前の測定ではなく「同じ時間帯の直前の
  測定」と比べる。指摘文にも両方の時刻と「どちらも朝」と書く。
- **時間帯で絞れるようにした。** ダッシュボードと水質の両方に置いた。
  一番見られるのはダッシュボードのグラフなので、そこを直さないと意味がない。
- **時間帯ごとの平均を並べた。** 「朝と昼で何℃違うのか」を数字で直接見せる。
- **グラフの横位置も時刻込みにした。** 同じ日の朝と昼が同じ位置に重ならない。

### 効果

サンプルデータ（朝18回・昼9回）で確認した。

| | すべての時間 | 朝だけ |
|---|---|---|
| 点の数 | 30 | 18 |
| 見え方 | ぎざぎざ（朝と昼の往復） | なだらかな季節の山 |

時間帯ごとの平均は 朝 24.6℃ / 昼 28.8℃ で、差は 4.2℃。
このぎざぎざは水温の変化ではなく、測る時間の往復だった。

誤検出も直った。朝22.4℃ → 昼29.5℃ では急変を出さず、
朝22.4℃ → 朝29.5℃ では「4日で +7.1℃・どちらも朝」と出す。

### 積み残し（更新）

- **写真を別端末へ移せない。**
- 水質は**水温と pH のみ**。
- **リマインド**がない。
- 匹数のグラフは**合計のみ**。
- 写真の並べ替え・絞り込みがない。
- **オフラインで開けない。**
- 作業ログには**時刻がない**。餌やりの時間帯を追いたくなったら同じ問題が出る。
- 要約の「推移」は時間帯が混ざったまま（各点に時刻は出している）。

## ループ #9 — 見た目と手ざわり

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| （指摘） | 業務アプリのような無機質さがある。もっと楽しく記録できるようにしたい |

正確な指摘だった。画面にある図形は**色付きの四角と折れ線だけ**で、
ビオトープらしさがどこにもなかった。

### 方向

「水面標本」— 野帳（フィールドノート）の手描き感に、生きている水面をひとつだけ置く。
にぎやかにするのではなく、主役を 1 つ作って周りは静かに保つ。

### 決めたこと

- **アイコンを描き起こした**（`src/icons.js`、24×24 の線画 20 個）。
  絵文字を使わなかったのは、環境によって絵が変わり、線の太さも揃えられないため。
  メダカ・ドジョウ・エビ・タニシは別々の姿で、**種類の名前から自動で選ぶ**
  （「ミナミヌマエビ」→エビ、「マドジョウ」→ドジョウ）。
- **ダッシュボードの主役を数字から水面に変えた。** canvas に水の階調・うねり・メダカを描く。
  **泳いでいる数は実際の飼育数に連動する**（合計 ÷ 8、最大 8 匹）。
  飾りにすると嘘になるので、記録の反映にした。
- **水温で色みが動く。** 22℃ を中心に、暖かいほど明るく、冷たいほど沈む。
- **水の色は季節で変える。** ただし**ボタンなどの色は動かさない**。
  対比を検証した値なので、季節で変えると読めなくなる可能性がある。
- **`prefers-reduced-motion` では 1 枚だけ描いて止める。**
- 作業ログの色付き四角をアイコンに置き換え、増減の四角は丸にした。
  増減は種類が多く密なので、記号より色の丸のほうが読みやすい。

### 変えなかったもの

グラフの系列色（水温の青・pH の橙・匹数の緑）。色覚特性を含めて検証済みの
組み合わせなので、雰囲気のために動かさない。

### 積み残し（更新）

## ループ #12 — 写真が保存できない環境への対応

### 再現できたこと

## ループ #13 — 通しで見直す

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| （指摘） | 改善ポイントを挙げて、直してほしい |

### 進めかた

新しい機能ではなく、いま出しているものの穴を探した。**先に「壊れている状態」を
再現するテストを書いてから直した。**そうしないと、直したつもりで直っていないもの
（ループ#12 の知らせのような）が混ざる。ブラウザ（Chromium）で実際に動かしている。

### 直したこと

**1. pH だけ測った日に、ダッシュボードから水温が消えていた。**
「いちばん新しい測定」をそのまま水温として読んでいた。pH だけ記録した翌朝に開くと
「—」になる。項目ごとに**その値を持つ最後の測定**を探すようにした。pH 側も同じ穴が
あった（水温だけ測ると pH タイルが「—」になる）。測っていないことと、直前の測定が
別の項目だったことは違う。

**2.「そろそろ交換」にだけ弱い記号が付いていた。** 4段階のうち一番強いのに ⓘ が出て
いた。気づきの側は同じ判定を正しく持っていたので、段階から記号を選ぶところを 1 つに
寄せて、判定を二重に書くのをやめた。

**3.「直近30日」に、ちょうど30日前の記録が入らなかった。** 切り取り位置を `Date.now()`
から取っていた。記録は日付までしか持たないのに境目だけ「いま何時か」で動くので、
夕方に開くと朝に開いたときより短い期間になる。日付の頭を起点にした。これで気づきの
「直近30日」と数え方も揃った。

**4. 記録があるのに「サンプルデータで試す」が押せた。** 生き物だけ空なら生き物の画面に
出る。押すと架空の測定30回と写真3枚が**本物の記録に混ざり**、立ち上げ日まで書き換わる。
まっさらなビオトープのときだけ出すようにした。立ち上げ日も、入っているなら残す。

**5. 埋め込み表示では、バックアップからの復元が黙って失敗していた。**
「保存してから読み直す」作りだったので、保存が使えない画面では書けないまま古いデータを
読み戻し、貼り付けた JSON が捨てられていた（初期状態に戻る）。画面に出ているのは
メモリの `state` なので、そちらを先に差し替える。保存されないことは知らせに出す。

| | 修正前 | 修正後 |
|---|---|---|
| 埋め込み表示で復元 | 「メインのビオトープ」（貼り付けた内容が消える） | 貼り付けた内容が出る |

**6. グラフの上に指が乗ると、ページを縦にスクロールできなかった。** 値を読むために
`touch-action: none` を置いていたが、これは縦も止める。横だけ受け取って縦はブラウザに
返す（`pan-y`）。スクロールが始まったら値の吹き出しも消す（`pointercancel`）。
記録するのはスマホなので、ここが止まると読むこと自体ができない。

**7. 薄い文字と段階の色が、実測すると 4.5:1 を下回っていた。**
ループ#9 で「対比を確かめた値」と書いたのはグラフの系列色のことで、こちらは
確かめていなかった。

| | 修正前 | 修正後 |
|---|---|---|
| muted（紙の上） | 2.90 | 4.64 |
| muted（カードの上） | 3.10 | 4.96 |
| 順調（緑） | 2.94 | 4.83 |
| 気になる（赤） | 4.22 | 5.11 |

`muted` は「時刻不明」「◯日前」など**読ませたい文字**にも使っている。暗い配色では
逆に沈むので、緑と赤は暗い側の値を別に置き直した（両方で 4.5:1 以上を確認）。

**8. 写真は 1 枚読めないと、まとめて全部落ちていた。** `Promise.all` に束ねていたため、
10枚選んで1枚が壊れていると 10枚とも入らない。1 枚ずつ受け止めて、読めた分は入れ、
読めなかった枚数を出す。あわせて `createImageBitmap` が無い・失敗する端末のために
`<img>` で読む道を足した。

**9. 画像の実体がない写真が、ただの空の四角だった。** バックアップの JSON に写真は
含まれないので、別のブラウザで復元すると記録だけが残る。そこに理由を出すようにした。

**10. 画面を切り替えても、前の画面で下まで見ていた位置に居座っていた。** 移った先の
見出しが画面の上に消えたまま出てくる。切り替えたときだけ先頭に戻す。

**11. こまごまとしたところ。** どの分岐にも当たらない form が送信されるとページが
再読み込みされる状態だったので先に止めた。タブのアイコンと説明文を付けた
（外部ファイルにすると `file://` と1ファイル版で読めないので、SVG を直接埋めた）。

### 途中の読み違え

「記録した直後にスクロールが飛ぶ」と読んで直しかけたが、**飛ばしていたのは検証
スクリプトのほうだった。** Playwright のクリックは対象の要素まで自動でスクロールする。
画面に触らずに送信して測り直したら、修正前も位置は動いていなかった。書きかけた
スクロール保持は戻した。直っていないものを直したことにするのと同じくらい、
壊れていないものを直すのも困る。

### 確かめたこと

| 見たもの | 結果 |
|---|---|
| 上の 1〜10 の再現テスト | 修正前 6 件失敗 → 修正後すべて通る |
| 各画面の追加・記録・削除・復元・要約 | 15 件すべて通る |
| スマホ幅（390px）で 6 画面 | 横にはみ出さない・グラフ上で縦に動く |
| 埋め込み（sandbox）表示 | 知らせが出る・復元が効く |
| コントラスト（ライト / 暗い） | 12 か所すべて 4.5:1 以上 |
| 1ファイル版・Artifact 版 | どちらも動く・エラーなし |

- **記録を後から直せない。** 打ち間違えたら消して入れ直すしかない。
- **保存できない表示では、記録もページを閉じると消える。**

## ループ #14 — WEB サービスにする

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| （要求） | いい感じに仕様が固まったので、より多くの人に使って貰えるように WEB サービス化したい |

### 何が「使って貰えない」原因だったか

仕様ではなく**配り方**だった。これまでの使い方は「リポジトリを取ってきて `index.html` を
開く」で、ビオトープを持っている人の大半はそこに辿り着けない。直すべきはアプリの中身では
なく、次の 4 つ。

| 詰まるところ | 直しかた |
|---|---|
| 手元にファイルが無いと開けない | URL ひとつで開ける（GitHub Pages） |
| 毎回ブラウザで URL を打つことになる | ホーム画面に追加してアプリのように開く |
| ビオトープの前は電波が弱い・圏外もある | 一式を控えて、通信なしで開けるようにする |
| 開いた人に、これが何なのか分からない | 初めて開いたときだけ短い説明を出す |

### 決めたこと

- **サーバは持たない。**「記録を預からない」は仕様の中心であって、制限ではない。
  預からなければ、アカウントも、規約も、流出も、運用費も要らない。置くのは静的な
  ファイルだけで足りる（`main` に入ると Actions が `dist/site` を組んで Pages に出す）。
- **オフラインは Service Worker で。** 控えるのは**アプリの一式だけ**で、記録は扱わない
  （記録は `localStorage` / `IndexedDB` にあり、通信しないので控える先がない）。
  - ページは**新しいほうを先に試す**。控えを先に返すと、直したものが何度読み込んでも
    古いまま出る。通信できなければ控えを返す — これが圏外で開ける道。
  - CSS・JS・アイコンは控えを即返して裏で取り直す。表示を待たせない。
  - 控えの取得は `addAll` を使わない。1 ファイル落ちただけで全部落ち、オフラインで
    何も開けなくなる。**取れた分を控える**（写真の取り込みと同じ考え方）。
  - 版は公開のたびに commit の SHA を埋める。中身が変われば、ブラウザが新しい版に
    気づく。気づかせる仕組みを持たないと、直したものが永久に出ない。
- **新しい版が来ても、勝手に読み込み直さない。** 入力中の記録が消える。
  画面の下に「新しい版があります」を出して、押されたときだけ入れ替える。
- **「ホーム画面に追加」は、追加できると分かったときだけ出す。** 出せない環境で押させると、
  何も起きないボタンになる。`beforeinstallprompt` が来たら `<html>` に印を付け、CSS で
  出す。iOS には頼む仕組みが無いので、iOS のときは**場所を教える案内**に切り替える。
- **置き場所はスマホに届くところ。** サイドバーの足元は狭い画面では畳まれて消えるので、
  ダッシュボードの末尾（暗くする / バックアップの隣）にも出す。追加するのはスマホなので。
- **初めて開いた人にだけ説明を出す。** 伝えるのは「何の道具か」「記録はこのブラウザの
  中だけで、送信しない」「ホーム画面に追加すると圏外でも開ける」の 3 つ。記録が入って
  いるブラウザには出さない（毎回どかす手間になる）。
- **公開向けのものは 1 ファイル版に入れない。** `file://` では Service Worker が動かず、
  manifest もアイコンの参照先も隣に無い。残すと 404 を出すだけなのでビルド時に外す。
  `src/web.js`（公開したページでだけ効くもの）を分けたのはこのため。
- **1 ファイル版も同じ URL の下に置く。** ブラウザの外へ持ち出したい人の受け皿になる。

### 作らなかったもの

- **アカウントと同期。** 端末をまたいで持ち運べないのは確かに不便で、いちばん要望が
  出そうなところ。それでも作らないのは、預かった時点で「記録はこのブラウザの中だけ」
  という約束が消えるから。持ち出しは JSON（バックアップ / 復元）で足りる。
- **アクセス解析。** 何人が使ったかは分からなくなるが、「どこへも送信しません」と
  書いた画面から送信するわけにはいかない。

### ついでに直したこと

**下に出る帯が、スマホでは画面の半分しか使えていなかった。**`left: 50%` だけで中央に
寄せると、置ける幅が右半分になる。左右を 0 にして `margin` で寄せる形に変えた。

| iPhone 13（390px）で測った | 修正前 | 修正後 |
|---|---|---|
| トーストの幅 | 195px（3行に折り返す） | 366px |
| 「新しい版があります」 | 文字もボタンも縦積み | 1 行に収まる |

### 確かめたこと

公開後と同じ形（`/meda-katsu/` の下）に配って、ブラウザで通した。

| 見たもの | 結果 |
|---|---|
| 初回の説明・2回目に出ないこと | 通る |
| Service Worker の登録と scope（サブパス配信） | 通る |
| 通信を切ってからの再読み込み | 開ける・記録もそのまま出る |
| manifest とアイコン 3 枚の取得 | すべて 200 |
| 新しい版 → 知らせ → 押して入れ替え → 古い控えの削除 | 通る |
| iOS 幅での追加の案内・横はみ出し | 通る（390px で収まる） |
| 1ファイル版（`file://`） | 動く・説明も追加ボタンも出ない・404 なし |
| PC / スマホでのエラー | どちらも 0 件 |

### 公開して分かったこと

**Pages を有効にするところだけは自動化できなかった。** 設定画面を触らずに済ませようと
`configure-pages` に `enablement: true` を付けたが、`main` に入った初回のビルドが
`Create Pages site failed. Resource not accessible by integration` で落ちた。

Pages を作る API は**リポジトリの管理権限**を要求する。ワークフローの `GITHUB_TOKEN` に
渡せるのは `pages: write` までで、これは「公開する」権限であって「公開先を作る」権限では
ない。組んだファイルを出すところまでは通っていて（`dist/site` は出来ていた）、
止まったのは置き場所を作る一手だけだった。

指定を外し、**一度きりの手作業として README に書いた**（Settings → Pages → Source を
「GitHub Actions」にする）。自動化できないものを自動化したことにして黙って失敗するより、
