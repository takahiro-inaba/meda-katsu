## ループ #1 — 台帳とグラフの土台

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 一番解決したいことは | 生き物の台帳管理 と 水質の推移を見ること（2つ） |
| どんな環境で使うか | PC の Web アプリ |
| データはどこに保存するか | ブラウザ内 |
| 最初に扱う管理対象は | 生き物 / 水質・水温 / 作業ログ |

### 決めたこと

- **サーバなし。** `localStorage` に JSON をまるごと保存する。バックアップは JSON のコピー &
  貼り付けで行う（ファイルのダウンロードは環境によって塞がれるため使わない）。
- **依存ライブラリなし。** グラフも SVG を直接組み立てる。`index.html` を開けば動く状態を保つ。
- **水温と pH は別グラフ。** ひとつの縦軸に 2 つの尺度を載せると値を読み違えるため。
- **削除は確認ダイアログではなく取り消し。** `confirm()` は環境によって出せないことがあり、
  やり直せる方が速い。
- **ビオトープは複数持てる形にした。** 要求としては聞いていないが、後から複数化すると
  既存データの作り直しが必要になるため、最初から `biotopeId` を持たせた（→ 要確認）。

### 積み残し（次のループの候補）

- 生き物の**増減の履歴**がない。いまは「今の数」だけを持ち、増えた / 減った経緯は残らない。
  繁殖や死亡を追いたいなら出来事として記録する形が要る。
- **水草・底床・機材**は未着手。最初の要求で外した分。
- 水質は**水温と pH のみ**。亜硝酸・硝酸塩・KH などは項目として持っていない。
- **リマインド**がない。「最後の水換えから何日」は出すが、通知や予定はない。
- **写真**が付けられない。`localStorage` の容量（数 MB）に収まらないため設計が要る。
- 期間の絞り込みは 30 / 90 / 全期間の固定。任意の期間指定はできない。

## ループ #2 — 生き物の増減の履歴

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | 生き物の増減の履歴 |
| ビオトープの複数対応は要るか | 複数あるので残す |

### 決めたこと

- **数を持たない。** `creature.count` を捨て、出来事（導入 / 繁殖 / 死亡 / 譲渡 / 数え直し）だけを
  保存する。いまの数は出来事を古い順に積み上げて計算する。
  数を直接書き換える作りだと「12匹が8匹になった」しか残らず、原因が消えるため。
- **「数え直し」を絶対値の置き換えにした。** ミナミヌマエビやタニシは正確に数えられない。
  ＋−では表せない「数えたら34匹だった」を扱えないと、記録が現実と合わなくなる。
- **合計匹数のグラフは階段状にした。** 数は出来事があった日にだけ変わり、その間は一定なので、
  点を斜めに結ぶと「毎日少しずつ増えた」という嘘になる。
- **旧データは自動で移行する。** v1 の `count` を導入日の「導入」1件に読み替える（`migrate()`）。
  保存キーは変えていないので、前のバージョンで記録していても開くだけで移る。
- **削除は生き物と履歴をまとめて消す。** 履歴だけ残っても参照先がない。取り消しは可能。

### 積み残し（更新）

- **水草・底床・機材**は未着手。
- 水質は**水温と pH のみ**。亜硝酸・硝酸塩・KH などは持っていない。
- **リマインド**がない。「最後の水換えから何日」は出すが、予定や通知はない。
- **写真**が付けられない。`localStorage` の容量に収まらないため設計が要る。
- 匹数のグラフは**合計のみ**。種類ごとの内訳は出せない。
- 期間の絞り込みは 30 / 90 / 全期間の固定。

## ループ #3 — 写真

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | 写真を残す |

### 先に確かめたこと

`file://` で開いたときに `IndexedDB` が使えるか。ここが駄目なら設計が変わるため、
コードを書く前に実機（Chromium）で確認した → **使える。割り当ては約 965MB**。

### 決めたこと

- **保存先を分けた。** 記録の JSON は `localStorage`、画像そのものは `IndexedDB`。
  `localStorage` は全体で 5MB 程度しかなく、写真 1 枚で使い切るため。
- **取り込み時に長辺 1600px の JPEG へ縮める。** 端末の写真は数MBあり、そのまま貯めると
  すぐ容量に当たる。4000×3000 の画像が 30KB になることを確認した。
- **バックアップ JSON に写真は含めない。** 貼り付けで運べる大きさを超えるため。
  ダイアログにその旨を明記した。写真を別端末へ移す手段は未提供（積み残し）。
- **写真の削除だけは取り消せない。** 画像は復元できないので、記録だけ戻しても壊れた参照が残る。
  逆に作業ログを削除したときは写真を消さず、「写真」画面に残す。
- **画像の表示は後から差し込む。** `IndexedDB` は非同期なので、描画は `img[data-photo]` の
  ままにしておき、読めた順に `src` を入れる。`objectURL` は使い回してちらつきを防ぐ。

### ついでに直したこと

種別チップ（作業ログ・増減）を押すと画面全体を描き直していたため、**入力途中のメモや
選択したファイルが消えていた**。ループ#1 から埋まっていたが、写真の添付を足したことで
表面化した。チップの選択状態だけを更新するようにした。

### 積み残し（更新）

- **写真を別端末へ移せない。** バックアップは記録のみ。
- **水草・底床・機材**は未着手。
- 水質は**水温と pH のみ**。
- **リマインド**がない。
- 匹数のグラフは**合計のみ**。種類ごとの内訳は出せない。
- 期間の絞り込みは 30 / 90 / 全期間の固定。
- 写真の並べ替え・絞り込みがない（新しい順のみ）。

## ループ #4 — 水草・底床・機材

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | 水草・底床・機材 |

最初の要求で外した最後の管理対象。これで当初の「ビオトープ全体」が一通り揃った。

### 決めたこと

- **3 つを別々の表にしなかった。** 水草・底床・機材は性質が違うが、「入れた → 使っている →
  撤去した」という一生は同じ。種別を持つ一つの表にして、画面上で 3 つに分けて見せる。
- **量は自由入力。** 「3株」「20L」「1台」と単位がばらばらで、数値型にすると単位が失われる。
- **生き物のような増減の履歴は付けなかった。** 水草の株数を正確に追う需要は薄く、
  ここで欲しいのは「いつから使っているか」。経過日数（底床なら交換の目安）を出す方を選んだ。
- **撤去は削除ではない。** `removedAt` を入れて一覧から外すだけにした。何をいつまで
  使っていたかは、うまくいかなくなったときに効いてくる記録なので消さない。
- ダッシュボードの「記録の数」タイルを「水草・設備」に差し替えた。件数は眺めても
  行動が変わらないが、設備の点数と内訳は変わる。

### 積み残し（更新）

- **写真を別端末へ移せない。** バックアップは記録のみ。
- 水質は**水温と pH のみ**。亜硝酸・硝酸塩・KH などは持っていない。
- **リマインド**がない。「最後の水換えから何日」は出すが、予定や通知はない。
- 匹数のグラフは**合計のみ**。種類ごとの内訳は出せない。
- 期間の絞り込みは 30 / 90 / 全期間の固定。
- 写真の並べ替え・絞り込みがない（新しい順のみ）。
- 水草の**トリミングや植え替え**は作業ログの「その他」に書くしかない。

## ループ #5 — スマホ対応

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | スマホ対応 |

ループ#1 で「PC の Web アプリ」と決めた前提が変わった。記録するのはビオトープの前
＝スマホ、というのは実際に触ってみて出てきた要求。**先に仕様を固めていたら拾えなかった。**

### 決めたこと

- **下部タブバーにしなかった。** 項目が 6 つあり、狭い画面に文字を並べると読めない。
  アイコンを新たに 6 つ作るより、上部固定の横スクロールするタブの方が正確で軽い。
  選んだタブは `scrollIntoView` で見える位置に寄せる。
- **表は 1 行 1 カードに組み替えた。** 横スクロールする表では右端の操作列に指が届かない。
  各セルに `data-label` を持たせ、CSS の `::before` で見出しを出す。
- **グラフは座標系そのものを狭くした。** SVG は横幅いっぱいに拡大縮小されるので、
  座標系と表示幅が離れるほど目盛りの文字だけが小さくなる。スマホでは 760 → 340 にして
  拡大率を 1 に近づけた（実測 0.98、目盛り 10.7px）。
- **入力欄の文字は 16px。** これ未満だと iOS が勝手に画面を拡大する。
- **固定ヘッダーは 2 段まで。** ブランド名とバックアップボタンを外し、
  バックアップはダッシュボードの末尾に移した。

### 詰まったところ

画面が横にはみ出す（586px > 390px）。原因は `.app` のグリッド指定 `1fr`。
これは `minmax(auto, 1fr)` の略で、中身の最小幅より縮まない。`minmax(0, 1fr)` に直した。
最初はタブ帯の負マージンを疑って直したが、それは症状の一部でしかなかった。

### 積み残し（更新）

- **写真を別端末へ移せない。** バックアップは記録のみ。
- 水質は**水温と pH のみ**。
- **リマインド**がない。
- 匹数のグラフは**合計のみ**。
- 期間の絞り込みは 30 / 90 / 全期間の固定。
- 写真の並べ替え・絞り込みがない。
- 水草の**トリミングや植え替え**は作業ログの「その他」に書くしかない。
- **オフラインで開けない。** Service Worker がないので、スマホのブラウザで
  ページ自体を読み込めない状況では使えない。

## ループ #6 — 記録からの気づき

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 次に何を作るか | AI サジェスト機能。日々の記録から AI がアドバイス |

### 先に確かめたこと

公開ページ（Artifact）から Claude API を呼べるか → **呼べない。**
ページに与えられる実行時の能力は `downloads` と `mcp`（claude.ai のコネクタ）だけで、
LLM を直接叩く口はない。CSP が外部ホストへの通信そのものを遮断する。
そもそもこのアプリはサーバも API キーも持っていない。

### 決めたこと

- **まず、外部に依存しない部分を先に作った。** 記録から機械的に導ける指摘を出す。
  キー不要・オフラインで動く・データが外に出ない。ここは要求の答えがどうであれ必要になる。
- **「AI が言っている」という見せかたをしない。** 中身は決定的な規則なので、
  名前は「気づき」にした。LLM を使っていないものを AI と呼ぶと、
  当たっているかの判断基準を読み手から奪う。
- **どの指摘にも根拠の数字を添える。** 「水換えから間があいています」だけでは動けない。
  「45日前。普段はおよそ12日おき」まで出して初めて判断できる。
- **段階は 4 つ**（気になる / 注意 / 参考 / 順調）。色だけに頼らず、記号と言葉も付けた。

見ているもの: 水温の高さと急変、pH の範囲と振れ幅、水換えの間隔（過去の中央値との比較）、
死亡と繁殖、数が長く動いていない生き物、底床の使用年数、記録と写真の途切れ。

### 未決

LLM に投げる版をどうするか。API キーをユーザー自身に入れてもらう形なら
1ファイル版では動くが、公開ページでは動かない。次のループで決める。

### 積み残し（更新）

- **写真を別端末へ移せない。**
- 水質は**水温と pH のみ**。
- **リマインド**がない（気づきは出るが、予定や通知はない）。
- 匹数のグラフは**合計のみ**。
- 期間の絞り込みは 30 / 90 / 全期間の固定。
- 写真の並べ替え・絞り込みがない。
- **オフラインで開けない。** Service Worker がない。

## ループ #7 — 貼り付け用の要約

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| LLM に問い合わせる版をどうするか | 貼り付け用の要約を出す（アプリは通信しない） |

### 決めたこと

- **アプリからは通信しない。** API キーも持たない。記録をまとめた文章を作り、
  コピーできるようにするだけ。どこでも動き、送り先は使う人が選ぶ。
- **統計に畳んでから渡す。** 測定 30 回ぶんをそのまま並べても読みにくい。
  最新・範囲・平均・間引いた推移（6点）にまとめた。サンプルデータで約 1,000 文字。
- **「相談したいこと」は入力欄を分けた。** 本文を書き換えると要約が壊れる。
  入力に応じて末尾だけ差し替える（`input` で textarea の値を直接更新し、
  描き直さないのでフォーカスも消えない）。
- **何が渡るかをダイアログに明記した。** 貼り付け先には記録がそのまま渡る。

### ループ#6 との関係

ループ#6 で「公開ページから LLM は呼べない」と分かった時点で、
外部に依存しない部分（気づき）を先に作り、依存する部分だけを次のループに残した。
結果として、要約には気づきの結果もそのまま含まれている。

### 積み残し（更新）

- **写真を別端末へ移せない。**
- 水質は**水温と pH のみ**。
- **リマインド**がない。

- 期間の絞り込みは 30 / 90 / 全期間の固定。

- **オフラインで開けない。** Service Worker がない。
- 要約に**写真は含まれない**（文章だけ）。
