## ループ #1 — 台帳とグラフの土台

### 聞いたこと / 答え

| 問い | 答え |
|---|---|
| 一番解決したいことは | 生き物の台帳管理 と 水質の推移を見ること（2つ） |
| どんな環境で使うか | PC の Web アプリ |
| データはどこに保存するか | ブラウザ内 |
| 最初に扱う管理対象は | 生き物 / 水質・水温 / 作業ログ |

### 決めたこと

- **サーバなし。** `localStorage` に JSON をまるごと保存する。バックアップは JSON のコピー &
  貼り付けで行う（ファイルのダウンロードは環境によって塞がれるため使わない）。
- **依存ライブラリなし。** グラフも SVG を直接組み立てる。`index.html` を開けば動く状態を保つ。
- **水温と pH は別グラフ。** ひとつの縦軸に 2 つの尺度を載せると値を読み違えるため。
- **削除は確認ダイアログではなく取り消し。** `confirm()` は環境によって出せないことがあり、
  やり直せる方が速い。
- **ビオトープは複数持てる形にした。** 要求としては聞いていないが、後から複数化すると
  既存データの作り直しが必要になるため、最初から `biotopeId` を持たせた（→ 要確認）。

### 積み残し（次のループの候補）

- 生き物の**増減の履歴**がない。いまは「今の数」だけを持ち、増えた / 減った経緯は残らない。
  繁殖や死亡を追いたいなら出来事として記録する形が要る。
- **水草・底床・機材**は未着手。最初の要求で外した分。
- 水質は**水温と pH のみ**。亜硝酸・硝酸塩・KH などは項目として持っていない。
- **リマインド**がない。「最後の水換えから何日」は出すが、通知や予定はない。
- **写真**が付けられない。`localStorage` の容量（数 MB）に収まらないため設計が要る。
- 期間の絞り込みは 30 / 90 / 全期間の固定。任意の期間指定はできない。
