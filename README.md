# メダ活 — ビオトープ台帳

メダカやドジョウのいるビオトープを記録する Web アプリ。PC でもスマホでも使えます。
記録はブラウザの `localStorage` に保存され、サーバは使いません。

## 使う

**https://takahiro-inaba.github.io/meda-katsu/**

開くだけで使えます。登録も設定もありません。手元で動かすなら、リポジトリの
`index.html` をブラウザで開いても同じものが動きます（ビルド不要）。

```
open index.html      # macOS
xdg-open index.html  # Linux
```

### ホーム画面に追加する

記録するのはビオトープの前なので、**アプリのように開けて、電波が無くても動く**形にしています。

- Android / PC（Chrome・Edge）— サイドバー、またはスマホではダッシュボードの末尾に出る
  「ホーム画面に追加」から
- iPhone / iPad — 共有ボタン →「ホーム画面に追加」（同じボタンから手順が出ます）

追加すると一式がこの端末に控えられ、圏外でも開けます。記録の置き場所は変わらないので、
ブラウザで書いたものがそのまま出ます。新しい版を出したときは、画面の下に
「新しい版があります」と出ます（押すまで読み込み直しません。入力中の内容が消えるため）。

### 配り方

`main` に入ると GitHub Actions が `dist/site` を組んで GitHub Pages に出します
（`.github/workflows/pages.yml`）。**サーバは持ちません。**記録を預からない作りなので、
置くのは静的なファイルだけで足ります。運用の費用も、預かったデータの責任も発生しません。

ブラウザの外へ持ち出したい人のために、
[1ファイル版](https://takahiro-inaba.github.io/meda-katsu/meda-katsu.html)（`meda-katsu.html`）も
同じ場所に置いています。保存してダブルクリックすれば、通信のない環境でも動きます。

## 見た目

ビオトープを見に行く前に開くものなので、業務ソフトに見えないようにしています。

- **アイコンは線画で描き起こしています。** メダカ・ドジョウ・エビ・タニシは別々の絵で、
  種類の名前から自動で選びます（「ミナミヌマエビ」ならエビの姿）
- **ダッシュボードの主役は生きている水面です。** 水温で色みが動き、メダカが泳ぎます。
  泳いでいる数は実際の飼育数に連動します（飾りではなく記録の反映）
- **水の色は季節で変わります。** 春・夏・秋・冬で 4 通り。ボタンなどの色は
  対比を確かめた値なので動かしません
- `prefers-reduced-motion` が設定されていれば、水面は 1 枚だけ描いて止まります
- **文字と背景の対比は実測して 4.5:1 以上に保っています**（明るい配色・暗い配色の両方）。
  薄い文字は「時刻不明」「◯日前」など読ませたいものにも使うため、薄さより読みやすさを取ります

**明るさはライトが既定です。** OS のダーク設定や、表示している画面側のテーマには追従しません
（水と紙の明るさを基調にしたいため）。暗くしたいときはサイドバーの「暗くする」から選べます。
選んだ状態はこのブラウザに残ります。

## 画面の幅で形が変わります

記録するのはビオトープの前、つまりスマホです。狭い画面では次のように組み替わります。

| | PC | スマホ |
|---|---|---|
| ナビ | 左の固定サイドバー | 上部に固定した横スクロールのタブ |
| 表 | 通常の表 | 1 行 1 カード（横スクロールでは操作列に指が届かないため） |
| グラフ | 座標系 760px | 座標系 340px（拡大率を 1 に近づけて目盛りを読める大きさに保つ） |
| 入力欄 | 2〜3 列 | 1 列・文字は 16px（iOS が拡大しないように） |

## できること

| 画面 | 内容 |
|---|---|
| ダッシュボード | 最新の水温、記録から見つけた気づき、生き物の合計、最後の水換えからの日数、水温の推移、最近の作業 |
| 生き物 | 種類・呼び名・導入日・メモの台帳。数は増減の履歴から計算し、合計匹数の推移をグラフで表示 |
| 水質 | 水温と pH の記録（日付＋時刻）、時間帯ごとの平均、推移グラフ（時間帯 × 30日 / 90日 / 全期間）、測定の一覧 |
| 作業ログ | 餌やり・水換え・足し水・掃除・観察の記録を時系列で表示。写真を添付できる |
| 水草・設備 | 水草 / 底床 / 機材を種別ごとに一覧。設置日からの経過日数を表示 |
| 写真 | その場でカメラを開いて撮影、または端末から選択。月ごとに並べて変化をたどる |

ビオトープは複数登録でき、サイドバーの選択で切り替えます。記録はビオトープごとに分かれます。

削除は取り消せます（削除後に出るトーストの「元に戻す」）。

### 測定時刻

水温は測る時間帯で数℃変わります。時刻を持たないと「水温が変わった」のか
「測る時間が違った」のか区別できません。そのため測定は日付と**時刻**を持ちます。

- 時間帯は 朝（4〜10時）/ 昼（10〜16時）/ 夕・夜（16〜4時）の 3 つ
- グラフは時間帯で絞れます。揃えて見ると、時刻の差ではない本当の変化が出ます
- 時間帯ごとの平均水温を並べて表示します（サンプルデータでは朝 24.6℃ / 昼 28.8℃）
- 「気づき」の急変判定は、**同じ時間帯どうし**でのみ比べます。朝と昼を比べて
  「急変」と言わないためです
- 時刻のない古い記録は「時刻不明」のまま扱います。後から作りません

### 気づき

ダッシュボードに出る「気づき」は、**記録から機械的に導ける指摘だけ**です。外部のサービスには
何も送りません。オフラインでも動きます。

見ているのは、水温の高さと急変、pH の範囲と振れ幅、水換えの間隔（普段の中央値との比較）、
死亡と繁殖の数、数が長く動いていない生き物、底床の使用年数、記録や写真の途切れです。

どの指摘にも**根拠にした数字を必ず添えています**。数字を見せずに助言だけ出すと、
合っているのか判断できず、そのうち読まれなくなるためです。

### まとめて相談する

「気づき」カードの「まとめて相談する」から、記録をまとめた文章を作れます。コピーして
Claude や ChatGPT に貼り付けて相談するためのものです。

**アプリはどこへも通信しません。**送り先は使う人が選びます。生成される文章には、
生き物の内訳と増減、水温と pH の統計と推移、水換えの間隔、水草・設備、直近の作業ログ、
アプリが見つけた気づきが入ります（サンプルデータで約 1,000 文字）。

### 生き物の数の持ちかた

「いま何匹か」は保存していません。保存しているのは**出来事**だけです。

| 出来事 | 数への効き方 |
|---|---|
| 導入 / 繁殖 | 足す |
| 死亡 / 譲渡 | 引く |
| 数え直し | その数で置き換える |

いまの数は、その生き物の出来事を古い順に積み上げて計算します。数を直接書き換える作りだと
「12匹だったのが今は 8匹」しか残らず、繁殖したのか死んだのかが消えてしまうためです。
ミナミヌマエビのように正確に数えられないものは「数え直し」で実測値に置き換えます。

### 水草・底床・機材の持ちかた

3 つは性質が違いますが「入れた → 使っている → 撤去した」という一生は同じなので、
種別を持つ一つの表で扱います。量は「3株」「20L」「1台」と単位がばらばらなので自由入力です。

撤去したものは削除せず `removedAt` が入り、一覧から外れます（「撤去したものも表示」で見られます）。
何をいつまで使っていたかは、後から効いてくる記録だからです。

### 写真の取り込み

「カメラで撮る」と「写真を選ぶ」を分けています。カメラを直接開く `capture` 属性を付けた
入力欄は、そのぶん端末のライブラリから選べなくなるためです。1 つの欄では両立しません。

- **カメラで撮る** — 背面カメラが直接立ち上がります（`capture="environment"`）。1 枚ずつ
- **写真を選ぶ** — 端末のライブラリから複数まとめて選べます
- カメラのボタンは**触る画面でだけ**出ます（`@media (pointer: coarse)`）。マウスの画面では
  意味がないため隠します
- 選んだあとに枚数とサムネイルが出ます。撮れたのかどうかが分からないまま
  「記録する」を押すことにならないようにしています

作業ログのフォームからも同じように撮影・選択できます。

### 写真の保存先

写真だけ保存先が違います。

| 中身 | 保存先 | 理由 |
|---|---|---|
| 記録（生き物・水質・ログ） | `localStorage` | 小さく、JSON でそのまま持ち出せる |
| 画像そのもの | `IndexedDB` | `localStorage` は全体で 5MB 程度しかなく、写真 1 枚で使い切る |

取り込むときに長辺 1600px の JPEG へ縮めます（4000×3000 の写真が 30KB 程度になります）。
`IndexedDB` の割り当てはブラウザによりますが数百MB あるため、数千枚は入ります。

読めない写真が混ざっていても、**読めた分はそのまま取り込みます**（読めなかった枚数を知らせます）。
まとめて失敗にすると、1 枚のために選んだ全部が入らなくなるためです。
画像の実体がない記録には、空の四角ではなく**理由を出します**。

**埋め込まれた表示では保存が使えないことがあります。** サンドボックス化された iframe の中では
`localStorage` も `IndexedDB` も `SecurityError` になります。その場合、写真はメモリに置いて
開いている間だけ使えるようにし、**保存できないことを画面のいちばん上に出します**。
すべて保存したいときは、ページを新しいタブで直接開くか、1 ファイル版をブラウザで開いてください。

## データの持ち出し

サイドバーの「バックアップ / 復元」から、記録を JSON で表示・コピーできます。
別のブラウザでその JSON を貼り付ければ復元できます。

**写真は JSON に含まれません。**容量が大きく、貼り付けで運べないためです。写真はこの端末に残ります。
別のブラウザで復元すると写真の記録だけが残るので、その枠には「画像はこの端末にありません」と出ます。

保存先は開いているブラウザの中だけです。別の端末とは共有されず、ブラウザのデータを消すと記録も消えます。

## 構成

```
index.html                 画面の骨組み
src/app.css                デザイントークンとスタイル（ライト既定、暗いのは任意）
src/icons.js               線画アイコン（24×24・すべて手書き）
src/app.js                 状態・保存・描画・グラフ・水面（依存ライブラリなし）
src/web.js                 URLで開いたときだけ効くもの（オフライン・追加・初回の案内）
service-worker.js          一式を控えて、圏外でも開けるようにする
manifest.webmanifest       ホーム画面に追加したときの名前・アイコン・開き方
assets/                    アイコンとリンク用の画像（scripts/build-icons.mjs で生成）
scripts/build-site.mjs     公開する一式を dist/site に組む
scripts/build-artifact.mjs 1枚のHTMLにまとめて dist/artifact.html を出力
.github/workflows/pages.yml main に入ったものを GitHub Pages へ出す
docs/loop-log.md           要求と決定の履歴
```

グラフは SVG を直接組み立てています。水温と pH は別々のグラフです
（ひとつの縦軸に 2 つの尺度を載せると値を読み違えるため）。
系列色は色覚特性を考慮した検証済みの組み合わせを使っています。

## 開発

```
node scripts/build-site.mjs       # 公開する一式を dist/site に組む
node scripts/build-artifact.mjs   # dist/artifact.html と1ファイル版を生成
node scripts/build-icons.mjs      # assets/ のアイコンとリンク用画像を作り直す
```

Service Worker は `http(s)` でしか動かないので、オフラインの確認は
`npx serve dist/site` のように配って行います（`file://` では登録されません）。

アイコンの生成にだけ Playwright を使います（`npm i -D playwright`）。書き出した PNG は
リポジトリに置いてあるので、絵を変えるとき以外は動かす必要はありません。生成環境の
フォントやレンダラの差でアイコンが静かに変わるのを避けるためです。
